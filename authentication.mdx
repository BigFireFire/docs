Bocha authenticates every API request using API key Bearer token authentication. Each request must include your API key in the `Authorization` HTTP header. There are no session cookies, OAuth flows, or temporary tokens to manage — your API key is your credential, and it works consistently across every endpoint in the Bocha platform.

## Getting your API key

Your API key is generated from the Bocha dashboard. Follow these steps to create one.

<Steps>
  <Step title="Log in to your account">
    Go to [app.bocha.ai](https://app.bocha.ai) and sign in with your email and password.
  </Step>
  <Step title="Open API Keys settings">
    From the main navigation, go to **Settings → API Keys**.
  </Step>
  <Step title="Create a new key">
    Click **Create New Key**, enter a descriptive label for the key (such as `production` or `staging`), and confirm. Bocha displays the full key value only once at creation time — copy it before closing the dialog.
  </Step>
</Steps>

<Warning>
  Treat your API key like a password. Never embed it directly in client-side code, commit it to a public repository, or share it in logs or error messages. If a key is ever exposed, revoke it immediately from the API Keys settings page and generate a replacement.
</Warning>

## Making authenticated requests

Add your API key to the `Authorization` header of every request using the Bearer token format:

```http
Authorization: Bearer YOUR_API_KEY
```

The following examples show how to make an authenticated request to create an order across common HTTP clients and languages.

<CodeGroup>

```bash curl
curl -X POST https://api.bocha.ai/api/v1/order/create \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"goodsId": 50021, "buyNum": 1, "addressId": 8863}'
```

```python Python
import requests

headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.post(
    "https://api.bocha.ai/api/v1/order/create",
    headers=headers,
    json={"goodsId": 50021, "buyNum": 1, "addressId": 8863}
)

print(response.json())
```

```javascript JavaScript
const response = await fetch('https://api.bocha.ai/api/v1/order/create', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ goodsId: 50021, buyNum: 1, addressId: 8863 })
});

const data = await response.json();
```

</CodeGroup>

## Authentication errors

When authentication fails, Bocha returns a standard HTTP error status along with a JSON response body containing a `code` and `msg` field. The table below covers the most common authentication-related errors.

| Status Code | Meaning | What to do |
|---|---|---|
| `401` | Missing or invalid API key | Check that the `Authorization` header is present and the key value is correct. Regenerate the key if needed. |
| `403` | API key lacks permission for this resource | Your key does not have access to the requested endpoint or resource. Review your key's permissions in the dashboard. |
| `429` | Rate limit exceeded | Your application is sending too many requests. Implement exponential backoff and retry logic, or contact Bocha support to discuss higher rate limits. |

<Info>
  All error responses from the Bocha API follow the same structure: `{"code": <status>, "msg": "<description>", "data": null}`. Your error handling logic can rely on the `code` field to identify and respond to specific failure conditions.
</Info>

<Tip>
  Store your API key in an environment variable such as `BOCHA_API_KEY` and read it at runtime. This keeps credentials out of your codebase and makes key rotation as simple as updating a single environment variable — no code changes required.

  ```bash
  export BOCHA_API_KEY="your_api_key_here"
  ```

  Then reference it in your code:

  ```python Python
  import os
  api_key = os.environ["BOCHA_API_KEY"]
  ```

  ```javascript JavaScript
  const apiKey = process.env.BOCHA_API_KEY;
  ```
</Tip>
