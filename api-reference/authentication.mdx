Every request you make to the Bocha API must be authenticated with an API key. Bocha uses the industry-standard Bearer token scheme — you include your key in the `Authorization` header of each HTTP request. There are no session cookies or OAuth flows to manage; a single header is all it takes to authenticate.

## API Key Format

Pass your API key as a Bearer token in the `Authorization` header on every request:

```http
Authorization: Bearer YOUR_API_KEY
```

Replace `YOUR_API_KEY` with the key you generate from the Bocha Dashboard. Keys are case-sensitive strings — copy them exactly as shown.

## Generating an API Key

You can create an API key at any time from the Bocha Dashboard:

1. Sign in to the [Bocha Dashboard](https://bocha.ai).
2. Navigate to **Settings** → **API Keys**.
3. Click **Create New Key**.
4. Give your key a descriptive name (e.g. `production-backend` or `staging-test`).
5. Copy the key immediately — it is only shown once at creation time.

You can create multiple keys for different environments or services and revoke any of them individually without affecting the others.

## Example Authenticated Request

The following examples show how to attach the `Authorization` header in common languages and tools.

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api.bocha.ai/api/v1/order/create \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "productId": "prod_abc123",
    "buyNum": 1
  }'
```

```python Python
import os
import requests

api_key = os.environ["BOCHA_API_KEY"]

response = requests.post(
    "https://api.bocha.ai/api/v1/order/create",
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    },
    json={
        "productId": "prod_abc123",
        "buyNum": 1,
    },
)

data = response.json()
print(data)
```

```javascript JavaScript (fetch)
const apiKey = process.env.BOCHA_API_KEY;

const response = await fetch("https://api.bocha.ai/api/v1/order/create", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    productId: "prod_abc123",
    buyNum: 1,
  }),
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## Key Security

Your API key grants full access to your Bocha account. Treat it like a password.

<Warning>
  **Never commit API keys to version control.** Hard-coding a key in your source code and pushing it to a repository — even a private one — is a common cause of credential leaks. Use environment variables or a secrets manager instead.
</Warning>

Follow these practices to keep your keys secure:

- **Use environment variables.** Read your key from the environment at runtime rather than embedding it in code (e.g. `process.env.BOCHA_API_KEY` in Node.js or `os.environ["BOCHA_API_KEY"]` in Python).
- **Restrict key scope.** Create separate keys for each environment (development, staging, production) so a leaked staging key cannot affect production.
- **Rotate compromised keys immediately.** If you suspect a key has been exposed, go to **Settings** → **API Keys** in the Dashboard, revoke the affected key, and issue a new one. Update all services using the old key before revoking it to avoid downtime.
- **Avoid logging keys.** Make sure your application's logging configuration does not capture raw request headers, which would record the key in plaintext log files.

<Tip>
  Use a `.env` file locally and load it with a library such as [python-dotenv](https://pypi.org/project/python-dotenv/) (Python) or [dotenv](https://www.npmjs.com/package/dotenv) (Node.js). Add `.env` to your `.gitignore` so it is never committed. In production, inject secrets through your hosting platform's environment variable management rather than deploying a `.env` file.
</Tip>

## Authentication Errors

If your request cannot be authenticated, the API returns one of the following errors:

| HTTP Status | `code` | `msg`                  | Meaning                                                                 |
| ----------- | ------ | ---------------------- | ----------------------------------------------------------------------- |
| `401`       | 40101  | Unauthorized           | The `Authorization` header is missing, malformed, or the key is invalid. |
| `403`       | 40301  | Forbidden              | The key is valid but does not have permission for the requested resource. |

If you receive a `401`, double-check that your key is being passed correctly and that it has not been revoked. If you receive a `403`, verify that your account has access to the endpoint you are calling — some endpoints require identity verification or a specific subscription tier. See the [Errors reference](/api-reference/errors) for a full list of application error codes.
