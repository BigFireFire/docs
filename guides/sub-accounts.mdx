Bank sub-account payments give enterprise customers a dedicated virtual bank account that sits within the Bocha platform and routes funds with full traceability. Each transaction generates a unique `order_flow_no` — a 36-character identifier that ties every payment to a specific fund movement in your bank's ledger, making reconciliation and auditing straightforward even at high transaction volumes.

## Prerequisites

Before enabling sub-account payments, confirm the following:

- You have completed identity verification — see [Identity Verification](/concepts/verification) for the required fields and submission process
- Your account is registered as a **business account** (not a personal account)
- Your business bank account has been verified and is in an active state

## Setting up and using sub-account payments

<Steps>

  <Step title="Complete verification">
    Sub-account payments are only available after your business bank account passes Bocha's verification process. Submit verification using `POST /api/v1/verification/submit` with the following fields:

    | Field                | Type    | Description                                             |
    |----------------------|---------|---------------------------------------------------------|
    | `account_no`         | String  | Your business bank account number.                      |
    | `account_name`       | String  | The registered name on the bank account.                |
    | `account_open_type`  | Integer | Account type: `0` for business, `1` for personal. Must be `0` for sub-account payments. |
    | `account_apply_date` | String  | The date the bank account was opened (ISO 8601 format). |

    ```bash
    curl -X POST https://api.bocha.ai/api/v1/verification/submit \
      -H "Authorization: Bearer $BOCHA_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "account_no": "6222021234567890123",
        "account_name": "Acme Technology Co., Ltd.",
        "account_open_type": 0,
        "account_apply_date": "2022-03-15"
      }'
    ```

    Check your verification status at any time with `GET /api/v1/verification/status`. Bocha typically completes verification within one business day.
  </Step>

  <Step title="Enable sub-account payments">
    Once verification is approved, activate the payment channel in your Dashboard:

    1. Navigate to **Dashboard → Settings → Payments**.
    2. Locate the **Sub-Account Payments** section.
    3. Click **Enable Sub-Account** and confirm the activation.

    Your sub-account is now ready to receive and initiate payments via the API.
  </Step>

  <Step title="Initiate a payment">
    Call `POST /api/v1/payment/sub-account` to trigger a sub-account payment for an existing order. Include the order number and any additional routing metadata required by your bank configuration.

    **Request body**

    | Field      | Type   | Required | Description                                      |
    |------------|--------|----------|--------------------------------------------------|
    | `order_no` | String | Yes      | The order number returned when the order was created. |
    | `remark`   | String | No       | Optional free-text memo attached to the transaction. |

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.bocha.ai/api/v1/payment/sub-account \
      -H "Authorization: Bearer $BOCHA_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "order_no": "ORD20260729001256",
        "remark": "Q3 software licence renewal"
      }'
    ```

    ```python Python
    import os
    import requests

    response = requests.post(
        "https://api.bocha.ai/api/v1/payment/sub-account",
        headers={
            "Authorization": f"Bearer {os.environ['BOCHA_API_KEY']}",
            "Content-Type": "application/json",
        },
        json={
            "order_no": "ORD20260729001256",
            "remark": "Q3 software licence renewal",
        },
    )

    result = response.json()
    if result["code"] == 200:
        flow_no = result["data"]["order_flow_no"]
        print(f"Payment initiated. Flow number: {flow_no}")
    else:
        print(f"Error {result['code']}: {result['msg']}")
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.bocha.ai/api/v1/payment/sub-account",
      {
        method: "POST",
        headers: {
          "Authorization": `Bearer ${process.env.BOCHA_API_KEY}`,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          order_no: "ORD20260729001256",
          remark: "Q3 software licence renewal",
        }),
      }
    );

    const result = await response.json();

    if (result.code === 200) {
      const { order_flow_no } = result.data;
      console.log(`Payment initiated. Flow number: ${order_flow_no}`);
    } else {
      console.error(`Error ${result.code}: ${result.msg}`);
    }
    ```

    </CodeGroup>

    A successful response includes the `order_flow_no` that uniquely identifies this sub-account transaction:

    ```json
    {
      "code": 200,
      "msg": "success",
      "data": {
        "order_no": "ORD20260729001256",
        "order_flow_no": "FA3C2E1B-8D47-4A90-B563-0012EF9A7C30",
        "pay_money": 199.80
      }
    }
    ```
  </Step>

  <Step title="Track via flow number">
    Store the `order_flow_no` returned in the payment response. This 36-character identifier is your reference for tracking the fund movement both within Bocha and in your bank's transaction records. Query `GET /api/v1/payment/record` at any time to retrieve the status and details associated with a flow number.
  </Step>

</Steps>

## Transaction tracking

The `order_flow_no` field is a 36-character UUID-format string that Bocha assigns to every bank sub-account transaction. It acts as a cross-system identifier: you can match it against your bank statement's reference field to confirm that a specific API payment corresponds to a specific fund movement.

To look up a specific sub-account transaction, retrieve your payment records and filter by `order_flow_no`:

<CodeGroup>

```bash curl
curl -G https://api.bocha.ai/api/v1/payment/record \
  -H "Authorization: Bearer $BOCHA_API_KEY" \
  --data-urlencode "order_flow_no=FA3C2E1B-8D47-4A90-B563-0012EF9A7C30"
```

```python Python
import os
import requests

response = requests.get(
    "https://api.bocha.ai/api/v1/payment/record",
    headers={"Authorization": f"Bearer {os.environ['BOCHA_API_KEY']}"},
    params={"order_flow_no": "FA3C2E1B-8D47-4A90-B563-0012EF9A7C30"},
)

records = response.json()
print(records)
```

```javascript JavaScript
const params = new URLSearchParams({
  order_flow_no: "FA3C2E1B-8D47-4A90-B563-0012EF9A7C30",
});

const response = await fetch(
  `https://api.bocha.ai/api/v1/payment/record?${params}`,
  {
    headers: {
      "Authorization": `Bearer ${process.env.BOCHA_API_KEY}`,
    },
  }
);

const records = await response.json();
console.log(records);
```

</CodeGroup>

### Example filtered response

```json
{
  "code": 200,
  "msg": "success",
  "data": [
    {
      "order_code": "ORD20260729001256",
      "pay_type": 4,
      "pay_money": 199.80,
      "order_flow_no": "FA3C2E1B-8D47-4A90-B563-0012EF9A7C30",
      "created_at": "2026-07-29T10:12:56Z"
    }
  ]
}
```

Use `order_flow_no` as the canonical reference when filing payment disputes, performing bank reconciliation, or responding to audit requests.

<Warning>
  Sub-account payments require completed **business** identity verification (`account_open_type=0`). Personal account verification (`account_open_type=1`) is not sufficient to enable this payment channel. Attempting to initiate a sub-account payment without approved business verification will return an authentication or permission error.
</Warning>

<Note>
  The `order_flow_no` field is `null` for all payment types other than bank sub-account (`pay_type=4`). If you are building a reconciliation system that handles multiple payment channels, use `order_code` as the shared key and treat `order_flow_no` as a supplementary identifier available only for sub-account transactions.
</Note>
